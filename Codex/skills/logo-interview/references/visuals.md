# Visual work in chat

Choose a method that makes the current decision visible with little setup.

## Medium and access

- **Searched references:** find and actually view relevant public work with available search/browser tools. Pinterest is optional. For inaccessible or sign-in-only material, use another public source or user attachments; do not bypass access controls.
- **Generated boards or studies:** use image generation only when available in this session and follow its input/output rules. In Codex prefer the built-in image tool; on other hosts discover the actual capability. Without generation, use viewed references and SVG studies. Do not create an SDK runner, request API keys, or change paid providers as setup.
- **Direct SVG:** useful for controlled shape, lettering, or proportion studies. Use editable paths/text; an embedded generated bitmap is not a vector logo.
- **Reference collage:** compose permitted, accessible source images when useful, under the host's editing rules. Do not install an image-processing pipeline before an interview. In Codex, use Python for image editing or compositing only when the user explicitly requests that method.

If the needed capability is unavailable, describe the limit and offer an available visual route. Text alone does not count as a viewed board. Follow host media-access/display rules; do not download media to bypass display restrictions.

An HTML moodboard is an available alternative: combine viewed references with captions, source links, palette swatches, and SVG studies in a small self-contained page. Render and actually view it through the host's supported display path before presenting it as a viewed board. If external images fail to load, use permitted local images or screenshots with source links, or another accessible reference; empty placeholders do not count as a board.

## References and their role

Select a coherent set that tests the actual uncertainty. Identify sources/authors when available and what property is useful. Distinguish viewed references, generated experiments, original SVG studies, and unverified suggestions. Do not claim to have viewed an inaccessible image or infer its appearance from a title.

Translate selected references into observable traits relevant to the brief: proportions, edges, curve tension, negative space, or relationships between parts. Separate the user's confirmed preference from your interpretation. If image inputs are supported and references drive the design, supply the actual viewed images with explicit roles. Transfer principles into an original mark rather than copying silhouettes or proposing borrowed trademarks as the user's logo.

Keep source links available when generation blends qualities. Generated work is not a faithful reproduction of reference pixels, documented typography, market evidence, or an originality check.

## Make a visual direction visible

A moodboard/direction board is an actual displayed composition communicating a coherent visual territory. Curate references or generated studies around the brief, label their roles, and explain the observable traits to explore. Use form/negative-space cues, lettering, palette, texture, or applications only as relevant. Atmospheric photographs, fixed image counts, and particular styles are optional. Keep incompatible territories distinguishable instead of mixing everything into one board.

A few separate reference links, an object-to-symbol study, or a grid of candidates does not by itself establish this direction. Caption the board's hypothesis, its basis in the brief, what is borrowed as a principle, and what remains open. Invite corrections to the interpretation; liking a board does not approve a specific logo. Text or placeholder boxes do not substitute for a requested visual board.

## Explore and develop

When construction remains open, vary meaningful mechanisms such as silhouette, negative space, letter integration, or relationships between parts. Keep the approved character and constraints. Once a construction is selected, focus revisions on its open properties. Use comparable scale and context; show the plain mark when mockups could hide defects. Add naming or application layouts only when useful and within scope.

For generation, specify purpose, provisional concept, reference traits, constraints, composition, and the question being tested. Distinguish required, permitted, and open choices. Label edit targets separately from style references; preserve confirmed dimensions. Keep exact names verbatim, inspect lettering, and put unreliable image labels or technical color values in chat.

## Inspect, compare, revise

Actually view outputs and compare them with the brief, references, and the intended difference before asking for a decision. Correct clear departures; identify unresolved mismatches. A link alone is not inspection. Show studies inline through the supported display path.

Explain what each proposal tests, then synthesize feedback and recommend the next useful action. If an optical adjustment is subtle, say so and show a useful scale/detail; do not present it as a new concept. If proposals miss, locate the failed decision before regenerating or reopening questions. Stop repeated near-duplicates and invented score chasing.

## Preserve candidate identity

Give each candidate a stable ID tied to its original file and each revision its own version. Use saved originals for selection sheets and exact repeats or inversions; regenerating an approved mark can change it. Preserve source geometry when compositing and follow host editing permissions. If an original is unavailable, identify the missing source or label a reconstruction explicitly.

For precise refinement, use editable geometry when appropriate. Compare any trace/reconstruction to the original before treating it as the same candidate. Export the selected version; inspect requested files for shape, transparency, and relevant sizes. Report deviations and untested reproduction limits. A raster study or an exported SVG alone does not establish production readiness.
