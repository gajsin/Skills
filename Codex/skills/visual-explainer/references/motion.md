# Motion that explains

Use this branch only for an animated deliverable. Reuse the chosen visual's
meaning and the bundled design system; do not redesign an approved still just
to make it move.

Animate the authored SVG elements or their HTML composition. Do not generate
image-model frames or substitute a generated clip for the editable scene.

## State and meaning

Define the initial state, the event or action, the visible consequence, and the
state the viewer needs time to read. A loop also needs an honest way back to
its beginning. Motion can show traversal, transfer, accumulation, delay,
selection, coupling, or feedback; the topic determines the mechanism.

Animate the property that represents the change. An unrelated orbit or wiggle
does not explain review, learning, collaboration, or progress by itself.
Keep stable elements and labels anchored so the viewer can compare states.
When changing topology, preserve identifiable objects or provide a clear
transition between representations.

For flows, track arrivals, departures, and retained items. For a repeated process,
distinguish a new cycle from an unexplained reset. For data, do not interpolate
through false states, change scale, or imply intermediate measurements that the
input does not support. Label a qualitative demonstration as a schematic when
its geometry could look like a quantitative result.

## Execute in the available host

Use an available animation workflow when it fits the deliverable. Hyperframes
can own a short HTML/SVG-based video when installed; it is not a dependency
of this skill. Otherwise use the host's available renderer for the requested
format. Never install a sibling skill, large stack, or paid service merely
because this reference names it. Follow actual host permissions and any
explicitly invoked production workflow.

Keep a deterministic timeline or time-to-state function that can reproduce
chosen frames. Preserve object identity during seeking. Prefer the project's
existing animation library; a simple motion does not justify a new stack.
Do not use unseeded randomness, wall-clock physics, or a perpetual local timer
as the source of truth for an exported video.

Treat geometry, captions, and timings as editable source. Deliver HTML when an
interactive animation is requested; use an actual video renderer for MP4 or
other requested media. Disclose a missing renderer rather than supplying a
different format under the requested filename. Audio is opt-in.

## Inspect the result

Inspect the start, the important change, and the ending, plus any nontrivial
intermediate state. Check the actual exported result, not just a code preview.
Verify labels, clipping, scale, continuity, and duration. For a seamless loop,
check the boundary in motion: a matching first/last image alone does not prove
continuous velocity or object identity. For an interactive preview, test its
pause/seek controls and reduced-motion state when present.

Report which format and states were inspected. Distinguish a verified static
design, an inspected preview, and a rendered video; one is not evidence that
all three have been checked.
