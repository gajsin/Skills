# Editor

Use on explicit invocation or request. Run one of the bundled Redaktura
workflows below; the user does not need to name an internal workflow. Use the
requested language. UI microcopy is outside this skill.

## Choose the workflow

| Request | Read and follow |
|---|---|
| Write or outline an article, guide, case study, long review, or newsletter | [Article](references/statya/guide.md) |
| Write or revise a social post, announcement, caption, hook, or adapt an article into a post | [Post](references/post/guide.md) |
| Write, structure, or audit landing-page copy, an About page, a profile, or a press release | [Promo](references/promo/guide.md) |
| Audit or edit existing prose without changing its format | [Editing](references/redaktura/guide.md) |
| Create, update, or audit an editorial policy, when requested | [Project voice](references/redpolitika/guide.md) |

Use the current task or a clearly referenced earlier task. If there is no task,
ask what to write or edit. Route by the requested output: a post from an article
uses Post. For an edit to an existing draft, follow Editing unless the request
is specifically for a format workflow, such as a social post hook.

Follow the chosen guide’s method, evidence rules, and output format. Its linked
guides and references are internal: read them when relevant, without asking the
user to invoke another skill.

Use the project’s `.agents/redpolitika.md` if it exists. Otherwise use the brief
and available examples; a missing policy does not block the task. Create or
update a policy only on request. A request to write or edit does not itself
authorize publication.
